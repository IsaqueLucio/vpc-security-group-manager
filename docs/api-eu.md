# API Documentation

This document describes the HTTP API currently implemented by the VPC & Security
Group Manager. Examples use `http://localhost:8000`; adjust the URL if the API
is running on another host.

## Overview

- Interactive documentation: <http://localhost:8000/docs>
- OpenAPI specification: <http://localhost:8000/openapi.json>
- All business routes require a valid JWT, except `POST /auth/login`.
- `POST /auth/register` requires an already authenticated user.
- Send the token in `Authorization: Bearer <token>`.
- VPC, Subnet, and IPAllocation identifiers are UUIDs.
- Network resources are soft-deleted: their response transitions to the
  `DELETED` status instead of the database row being physically removed.

Shell examples use `jq` to extract JSON values.

`/docs`, `/redoc`, and `/openapi.json` are FastAPI pages/documents; they are not
business routes. The specification and Swagger UI are accessible without a
token.

## Expected Workflow

1. Obtain an admin account through operational provisioning. There is no public
   endpoint to create the first admin.
2. Log in at `POST /auth/login` to obtain a token.
3. Use an authenticated account to register regular users with
   `POST /auth/register`.
4. Log in as each user. Each person must use their own bearer token to create
   and query resources.
5. Create a VPC. It starts as `PENDING` and transitions to `ACTIVE` after the
   configured delay.
6. Create Subnets inside the VPC; the system chooses a free CIDR by default or
   accepts a valid manual CIDR.
7. Create IPAllocations inside a Subnet; by default, the first free usable IP
   is selected.
8. Use PATCH to update only editable fields; use DELETE to mark resources as
   `DELETED`.

### Creating Users and Obtaining Tokens

Login accepts `application/x-www-form-urlencoded` form data. The `username`
field must contain the registered email address.

```bash
ADMIN_TOKEN=$(curl -sS -X POST http://localhost:8000/auth/login \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  --data-urlencode 'username=admin@example.com' \
  --data-urlencode 'password=<admin-password>' | jq -r .access_token)
```

An authenticated account can register a new user. The endpoint only creates
regular users; `role` cannot be specified in the request body.

```bash
curl -sS -X POST http://localhost:8000/auth/register \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{
    "username": "alice",
    "email": "alice@example.com",
    "password": "StrongPassword@123"
  }'
```

The password must have at least 8 characters, one uppercase letter, one number,
and one special character from `!@#$%^&*()_+-=`.

Log in with each account you intend to use:

```bash
ALICE_TOKEN=$(curl -sS -X POST http://localhost:8000/auth/login \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  --data-urlencode 'username=alice@example.com' \
  --data-urlencode 'password=StrongPassword@123' | jq -r .access_token)
```

The token is a signed bearer token containing the user ID and role issued at
login. The API loads the user by ID and uses the role currently stored in the
database to authorize operations. Inactive or nonexistent users are rejected
with `401`, even when presenting an unexpired JWT.

## Authentication, Ownership, and Roles

### Regular User

- Only lists and operates VPCs they own.
- Ownership of Subnets and IPAllocations is determined by following the
  Subnet → VPC → owner relationship; `owner_id` exists only on the VPC.
- Attempting to read, update, delete, or create a resource under a parent they
  do not own returns `404 Not Found`.
- Cannot specify `owner_id` when creating a VPC.

### Admin

- Can list and operate VPCs, Subnets, and IPAllocations belonging to any owner.
- Can create a VPC for another user by sending `owner_id`.
- If `owner_id` is omitted, the created VPC belongs to the admin.
- Quota, name uniqueness, and overlap checks upon creation are evaluated against
  the target owner.

The `GET /users/me` endpoint returns the authenticated account's profile. The
`/admin/users` routes require the `admin` role; this administrative
authorization returns `403` when the authenticated account is not an admin.

## Response and Error Format

Application error responses follow this format:

```json
{
  "detail": "Error description."
}
```

Input validation errors generated by FastAPI may return an array of details in
`detail`.

| HTTP | Common Usage |
| --- | --- |
| `200 OK` | Query, update, or soft deletion completed |
| `201 Created` | User, VPC, Subnet, or IPAllocation created |
| `204 No Content` | User deleted via administrative route |
| `401 Unauthorized` | Missing, invalid, or expired JWT; nonexistent/inactive account; invalid credentials |
| `403 Forbidden` | Authenticated user without admin role attempting to access an admin-only route |
| `404 Not Found` | Nonexistent, deleted, or another user's resource |
| `409 Conflict` | Duplicate name/CIDR/IP, overlap, quota exceeded, address exhaustion, or state preventing the operation |
| `422 Unprocessable Entity` | Invalid body or parameter; non-canonical/reserved CIDR; non-editable field |
| `503 Service Unavailable` | Timeout while waiting for an allocation lock; response includes `Retry-After` |

A second deletion of a resource that is already `DELETED` returns `404`.

## Authentication and User Endpoints

### `POST /auth/login`

Public. Authenticates via email and password.

**Content-Type:** `application/x-www-form-urlencoded`

| Field | Required | Description |
| --- | --- | --- |
| `username` | Yes | Account email |
| `password` | Yes | Password |

**Response `200`:**

```json
{
  "access_token": "<jwt>",
  "token_type": "bearer"
}
```

Incorrect credentials or an inactive user return `401`.

### `POST /auth/register`

Requires a JWT from an active account. Creates a regular user only.

**Body:**

```json
{
  "username": "alice",
  "email": "alice@example.com",
  "password": "StrongPassword@123"
}
```

- `username`: 3 to 50 characters.
- `email`: valid and unique email address.
- `password`: at least 8 characters, with an uppercase letter, a number, and an
  allowed special character.
- `role` and `is_active` are not accepted as configuration fields upon creation;
  the route always creates an active account with the `user` role.

**Response `201`:**

```json
{
  "id": 12,
  "username": "alice",
  "email": "alice@example.com",
  "role": "user"
}
```

Passwords or password hashes are never included in the response. A duplicate
email or username returns `409`.

### `GET /users/me`

Requires JWT. Returns `id`, `username`, `email`, and `role` of the authenticated
account.

### `GET /`

Requires JWT. Returns the API name and initialization status.

### `GET /health`

Requires JWT. Returns `{"status":"ok"}` when the API process is responding.

### `GET /admin/users`

Requires `admin` role. Returns the list of users in `UserRead` format.

### `DELETE /admin/users/{user_id}`

Requires `admin` role. Deletes the user and returns `204 No Content`. An admin
cannot delete their own account (`409`); a nonexistent user returns `404`.

## VPC Endpoints

Possible statuses: `PENDING`, `ACTIVE`, `ERROR`, and `DELETED`. Upon creation,
the VPC starts in `PENDING`; a background task transitions it to `ACTIVE` after
the configured delay. The task runs in-memory and does not persist if the API
process stops.

CIDRs must be canonical IPv4 ranges with a prefix between `/16` and `/28`. The
CIDR cannot have host bits set outside the network mask or fall within a
reserved range. Public CIDRs are accepted, but the response includes a warning.

### `POST /vpcs`

Creates a VPC for the authenticated user. A duplicate name, duplicate CIDR, or
overlap with an active VPC of the same owner results in `409`; exceeding the
per-owner quota also results in `409`.

**Body for regular user:**

```json
{
  "name": "production",
  "cidr_block": "10.20.0.0/16",
  "description": "Production network",
  "region": "us-east-1"
}
```

`name` must be 3 to 100 characters. `description` is optional. `region` must be
one of the regions listed in `GET /docs`/OpenAPI.

Regular users do not have the `owner_id` field in their schema; sending this
field results in a `422` rejection.

**Admin creation for another user:**

```json
{
  "name": "production",
  "cidr_block": "10.20.0.0/16",
  "description": "Production network",
  "region": "us-east-1",
  "owner_id": 12
}
```

`owner_id` is optional for admins and must be a positive integer. Omitting it
assigns the VPC to the admin. The target owner must exist. Name uniqueness,
quota, duplicate CIDR, and overlap are checked against the specified owner.

**Response `201` (example):**

```json
{
  "id": "de305d54-75b4-431b-adb2-eb6b9e546014",
  "name": "production",
  "cidr_block": "10.20.0.0/16",
  "description": "Production network",
  "region": "us-east-1",
  "status": "PENDING",
  "created_at": "2026-11-05T12:00:00Z",
  "updated_at": "2026-11-05T12:00:00Z",
  "warnings": []
}
```

`warnings` will contain a message if the CIDR is publicly routable.

### `GET /vpcs`

Lists active VPCs. Regular users see their own; admins see VPCs across all
owners.

Query parameters:

| Parameter | Default | Constraints |
| --- | --- | --- |
| `skip` | `0` | Greater than or equal to zero |
| `limit` | `20` | Between 1 and 100 |

### `GET /vpcs/{vpc_id}`

Returns an active VPC visible to the account. A user without ownership receives
`404`.

### `PATCH /vpcs/{vpc_id}`

Updates only `name` and/or `description`. Send at least one field. `name` must
be 3 to 100 characters and cannot be `null`; `description` can be `null`.
`status`, `cidr_block`, `region`, and `owner_id` are not editable via PATCH.

```json
{
  "name": "production-renamed",
  "description": "Updated description"
}
```

Disallowed fields, including `status`, return `422`.

### `DELETE /vpcs/{vpc_id}`

Marks the VPC as `DELETED`. Within the same transaction, it also marks active
descendant Subnets and IPAllocations as `DELETED`. Returns the deleted VPC.

## Subnet Endpoints

Possible statuses: `PENDING`, `ACTIVE`, `ERROR`, and `DELETED`. A Subnet can be
created while the VPC is `PENDING`; a VPC in `ERROR` or `DELETED` does not
accept new Subnets.

Required type:

- `PUBLIC`
- `PRIVATE`

The CIDR must be canonical IPv4, have a prefix from `/16` to `/28`, be contained
within the VPC, and not overlap any other active Subnet in the same VPC.

### `POST /vpcs/{vpc_id}/subnets`

Creates a Subnet under an accessible VPC.

**Automatic allocation (default `/24`):**

```json
{
  "name": "private-a",
  "type": "PRIVATE"
}
```

To choose a different size, use `prefix_length` (16 to 28):

```json
{
  "name": "private-b",
  "type": "PRIVATE",
  "prefix_length": 26,
  "availability_zone": "us-east-1a"
}
```

**Manual allocation:**

```json
{
  "name": "public-a",
  "type": "PUBLIC",
  "cidr_block": "10.20.1.0/24",
  "availability_zone": "us-east-1a"
}
```

Send either `cidr_block` or `prefix_length`, not both. `availability_zone` is
stored without validating whether it matches the VPC region.

Automatic allocation locks the VPC row while selecting the first free block. The
lock timeout is configured via `DATABASE_LOCK_TIMEOUT_MS` (default `5000` ms).
A timeout returns `503` with `Retry-After`; an overlap conflict returns `409`.

**Response `201` (example):**

```json
{
  "id": "39a00000-0000-4000-8000-000000000001",
  "vpc_id": "de305d54-75b4-431b-adb2-eb6b9e546014",
  "name": "private-a",
  "cidr_block": "10.20.0.0/24",
  "type": "PRIVATE",
  "availability_zone": null,
  "status": "PENDING",
  "created_at": "2026-11-05T12:00:00Z",
  "updated_at": "2026-11-05T12:00:00Z",
  "total_ips": 256,
  "usable_ips": 251,
  "available_ips": 251
}
```

`total_ips` is the mathematical total of addresses. `usable_ips` excludes the
first four and the last address of the Subnet; `available_ips` subtracts active
allocated IPs from `usable_ips`.

### `GET /vpcs/{vpc_id}/subnets`

Lists active Subnets of the VPC, after validating that the VPC belongs to the
user or that the user is an admin. Accepts `skip` (default `0`, minimum `0`) and
`limit` (default `20`, between `1` and `100`).

### `GET /subnets/{subnet_id}`

Returns an accessible active Subnet with capacity and availability metrics.

### `PATCH /subnets/{subnet_id}`

Updates only `name` and/or `type`. Send at least one field. `name` must be 1 to
100 characters; `type` is `PUBLIC` or `PRIVATE`. Status, CIDR, VPC, and
availability zone cannot be modified via PATCH.

### `DELETE /subnets/{subnet_id}`

Marks the Subnet and its active IPAllocations as `DELETED` in the same
transaction. Returns the deleted Subnet.

## IPAllocation Endpoints

IPAllocation represents the reservation of a usable IPv4 address within a
Subnet. The network address, the following three addresses, and the broadcast
address (first four plus the last) are reserved.

### `POST /subnets/{subnet_id}/ip-allocations`

Creates an allocation. An empty body automatically selects the first free IP.

```json
{}
```

To request a specific IP:

```json
{
  "ip_address": "10.20.0.20",
  "description": "Application server"
}
```

A manual IP must be a usable IPv4 address, belong to the Subnet, and not be
already allocated. A reserved or out-of-range IP returns `422`; a duplicate IP
returns `409`. If no addresses are available, it returns `409`.

Creation locks the Subnet row while checking availability and persisting the
allocation. A lock timeout returns `503` with a `Retry-After` header. Active
uniqueness is also enforced by a partial unique index in the database.

**Response `201` (example):**

```json
{
  "id": "39a00000-0000-4000-8000-000000000002",
  "subnet_id": "39a00000-0000-4000-8000-000000000001",
  "ip_address": "10.20.0.20",
  "description": "Application server",
  "status": "ACTIVE",
  "created_at": "2026-11-05T12:00:00Z",
  "updated_at": "2026-11-05T12:00:00Z"
}
```

### `GET /subnets/{subnet_id}/ip-allocations`

Lists active IPAllocations of an accessible Subnet. A nonexistent, deleted, or
another owner's Subnet returns `404`.

### `GET /ip-allocations/{allocation_id}`

Returns an accessible active IPAllocation. A deleted allocation or one belonging
to another owner returns `404`.

### `DELETE /ip-allocations/{allocation_id}`

Marks the allocation as `DELETED` and returns the updated representation. The
address becomes available for reuse within the same Subnet.

## Complete Two-User Example

This example assumes `ADMIN_TOKEN` has been obtained as shown above and `jq` is
installed. The admin registers Alice and Bob; Alice creates a VPC, Subnet, and
IP allocation; Bob cannot read Alice's VPC; the admin can.

```bash
# Create regular accounts (the registration route requires an authenticated account).
curl -sS -X POST http://localhost:8000/auth/register \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"username":"alice","email":"alice@example.com","password":"StrongPassword@123"}'
curl -sS -X POST http://localhost:8000/auth/register \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"username":"bob","email":"bob@example.com","password":"StrongPassword@123"}'

# Log in as each user.
ALICE_TOKEN=$(curl -sS -X POST http://localhost:8000/auth/login \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  --data-urlencode 'username=alice@example.com' \
  --data-urlencode 'password=StrongPassword@123' | jq -r .access_token)
BOB_TOKEN=$(curl -sS -X POST http://localhost:8000/auth/login \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  --data-urlencode 'username=bob@example.com' \
  --data-urlencode 'password=StrongPassword@123' | jq -r .access_token)

# Alice creates a VPC.
VPC_ID=$(curl -sS -X POST http://localhost:8000/vpcs \
  -H "Authorization: Bearer $ALICE_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"name":"alice-vpc","cidr_block":"10.20.0.0/16","region":"us-east-1"}' \
  | jq -r .id)

# Alice creates a Subnet and automatically gets the first /24 block.
SUBNET_ID=$(curl -sS -X POST "http://localhost:8000/vpcs/$VPC_ID/subnets" \
  -H "Authorization: Bearer $ALICE_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"name":"private-a","type":"PRIVATE"}' | jq -r .id)

# Alice automatically reserves the first usable address.
curl -sS -X POST "http://localhost:8000/subnets/$SUBNET_ID/ip-allocations" \
  -H "Authorization: Bearer $ALICE_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{}'

# Bob is not the owner: receives 404 (not 403).
curl -i -H "Authorization: Bearer $BOB_TOKEN" \
  "http://localhost:8000/vpcs/$VPC_ID"

# The admin can query resources belonging to any owner.
curl -i -H "Authorization: Bearer $ADMIN_TOKEN" \
  "http://localhost:8000/vpcs/$VPC_ID"
```

## Related Configuration Variables

See `.env.example` for the full list. The main variables affecting the
documented workflows are:

| Variable | Effect |
| --- | --- |
| `SECRET_KEY` | JWT signing key; use a random secret of at least 32 characters |
| `ALGORITHM` | JWT algorithm; default `HS256` |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | Token expiration time; default `30` minutes |
| `VPC_LIMIT_PER_OWNER` | Active VPC quota per owner; default `5` |
| `VPC_PROVISIONING_DELAY_SECONDS` | Delay before a VPC transitions from `PENDING` to `ACTIVE`; default `30` seconds |
| `DATABASE_LOCK_TIMEOUT_MS` | Maximum wait time for an allocation lock; default `5000` ms |

## Operational Notes

- The API uses PostgreSQL and the schema must be applied with `alembic upgrade head`.
- Never commit or expose `SECRET_KEY`, passwords, or tokens in public repositories or logs.
- VPC activation runs as an in-memory process task; it is not a durable queue.
- The complete list of routes and schemas is available at `/docs` and
  `/openapi.json`.
